# Static native Chat capture proposal (stage 1, partial)

This folder is wired into CI only through a **default-off manual input**.
The isolated harness and wiring received source review; hosted execution remains
pending on the published exact commit. Existing Usage/Workbench recipes and counts
are unchanged. Runtime application source is unchanged by this harness.

## Approved executed-input scope

Only two native keyboard actions: `Ctrl+1` opens the single persisted session,
then `Ctrl+Up` selects the previous user turn. No pointer click, hover, selection,
clipboard, scroll, text entry, prompt, compact, model or authentication action.
Both capture cases are static persisted content. Images are native X11 client
captures, never resized, not headless rendered fixtures.

C15 Context details is explicitly **BLOCKED / NOT_CAPTURED**, not passed:
real Pi1.4's `dist/core/sdk.js` restores a session model only when
`modelRuntime.hasConfiguredAuth(provider)` is true. The clean credential-free
fixture returns an `unknown` model, contextWindow0, and no `contextUsage`.
There is consequently no verified percent-label click target. No fake key,
set_model call, model CLI override or guessed ring coordinates are introduced.
The source-recorded400000 last-assistant tokens are not misreported as a known
live context. Session stats still correctly total411000 across24 messages.

Selection/hover and synthetic retry/compaction protocol states are future,
separately approved increments. No C08/C14/C15 or full-parity PASS is inferred.

## Same input and entry path

`materialize.py` refuses existing/symlinked roots and creates a fresh isolated
HOME/workspace, one Pi v3 session with12 user turns, fixed content/timestamps,
source font/theme/density preferences, and disabled auto title. The default
physical hosted location must be exactly `/tmp/orbit-chat-static-fixture`:
Pi validates that the session header's cwd exists. Both Rust299a32b and the
frozen Go build open the same sidebar slot through native Ctrl+1. The Go-only
`--session` entry is deliberately not used.

`preflight.py` uses actual Pi1.4, not a fake child, with only switch_session,
get_state, get_messages and get_session_stats. No inference/action command is
accepted. Both child I/O and lifetime are bounded; responses, binary hash,
actual Node/Pi versions and stderr are recorded. A fresh fixture is mandatory.
An empty auth.json generated by Pi is allowed; a nonempty credential file
invalidates the fixture. Fixed inputs may not change, except the original
strictly validated single `orbit:workflow` build metadata append already used
by Workbench. It never allows a new message, model, usage or title entry.

## Input safety and evidence

`capture.py` reuses existing OCR readiness but limits the recipe to the two
specific keys and output names. Before each input it verifies process start
identity, executable, window PID, visibility, active window and1470×922 client
bounds. A fresh whole-window image and expected prior-state phrases must exist;
image hash and a maximum5sec evidence age are rechecked before dispatch.
An uncertain input failure is recorded and never retried. No prior output may
be reused. A live pinned Pi RPC descendant is required for readiness, but that
is explicitly not claimed to prove an acknowledged request or provider run.

The artifact records full PNGs, OCR/raw hashes, prior-state evidence, requested
and sent keys, PID/start/argv ownership, fixture integrity, actual versions and
source/binary hashes. OCR readiness is only READY_FOR_MANUAL_REVIEW. Pixel
comparison and actual selected-state acceptance remain UNREVIEWED/NOT_COMPARED;
font resolution, clocks, caret/animation phase are not frozen.

`workflow_dispatch.inputs.capture_chat_stage1` is boolean, default false. Both
pinned Rust and Go steps receive the same expression; push/PR runs keep Chat off.
The existing hosted wrapper launches a separate Chat process/home after existing
captures, with outputs under `chat/` and an independent two-case manifest. The
existing suite image count is unchanged. Context remains explicitly BLOCKED.

The existing workflow already installs Node22.23.4, Pi1.4.0, Xvfb/Openbox,
xdotool, wmctrl, ImageMagick and Tesseract. No new package, permission or secret
is required. The shell refuses other hosts/displays and Node versions, and any
existing fixed fixture root (including dangling links), without deleting it.
Cleanup signals only the launched group whose PID/starttime/group-leader identity
still matches; loss of identity fails closed rather than targeting another process.
The diff adds path filters and Python regressions; it does not dispatch anything.
Do not add these two cases to an existing pixel-comparison count automatically.

## Owned Pi discovery: threaded child regression

The first Chat attempt stopped in STARTUP before Ctrl+1: 30 observations lacked
an accepted RPC descendant. The native image showed the fixture sidebar and
Connected. This does not establish lazy Pi startup: Rust app.rs1289 spawns at
construction; Go run.go269 opens the runtime, manager.go launches start on a
worker. No input was recorded, and this change never retries uncertain input.

The old scanner read only `/proc/PID/task/PID/children`. Linux documents this
as children of the specified **task/thread**, not all threads in a process:
https://www.kernel.org/doc/html/latest/filesystems/proc.html#proc-pid-task-tid-children-information-about-task-children
Missing nonleader-thread children is a supported hypothesis for that artifact,
not a proved hosted root cause until the controlled thread regression executes.

Discovery now reads all task children only within the owned ancestry, bounded
by 64 processes and 1024 thread entries. Each edge must retain its parent PID,
starttime/executable identity and live ancestry; exact pinned CLI path plus
`--mode rpc` still applies. Vanished threads/children provide no evidence.
Capture and pre-input checks retain root/window/image guards; pre-input repeats
discovery and requires a previously observed pinned child identity still live.
STARTUP, post-open and pre-PrevTurn all retain the RPC gate unchanged.

A separate Ubuntu `proc-guard-regression` job uses stdlib only: a live worker
thread launches its own controlled Python child with fixture RPC argv, not Pi
inference or authentication. Both renderer jobs depend on its success. Missing
proc task-children support fails in GitHub or with ORBIT_REQUIRE_PROC_CHILDREN=1;
local sandboxes lacking the file explicitly skip this one real-process test.
Deterministic proc fixtures test identity churn, wrong parent/CLI, vanished task,
and fanout rejection but do not substitute for the required hosted proof.
No automatic rerun or new one-shot marker is introduced here.
