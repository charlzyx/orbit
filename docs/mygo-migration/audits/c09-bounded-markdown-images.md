# C09: bounded remote/data Markdown raster images (unreleased)

## Source contract and scope

Rust baseline `299a32bc87fe3d4851bdb902d9c03dcf9bf99cac`,
`crates/orbit-pi/src/transcript_view.rs`: standalone Markdown/HTML image parsing
5655–5688, durable signed GitHub URL normalization 5699–5735, image sizing,
alt fallback and link action 6291–6350. This batch restores standalone HTTP(S)
and base64 data raster rendering; it is **not complete C09/Rust parity**.

The existing `markdown.FileImages` loader and local-file path remain unchanged.
The public Markdown block hook handles standalone image paragraphs and single
HTML `img` tags; other HTML is not executed, and event/style attributes are ignored.
Inline images mixed with prose retain the existing renderer's alt-text behavior.
Mixed local/remote image paragraphs route local elements through the original loader.

Loaded images retain natural aspect, fit available width, show alt on failure,
and support the native image/link action. Signed GitHub assets normalize to the
source's durable URL. Data images open the existing native decoded-image preview
rather than passing an untrusted data URL to an external application.

## Deliberate safety boundaries

- HTTP(S) only, no URL userinfo. No ambient proxy, cookie jar, auth, or Referer.
  Each redirect is validated, with at most five requests and no HTTPS downgrade.
- DNS resolves once per new connection, validates **all** answers, then dials the
  exact validated literal IP. Reject private, loopback, mapped-private, link-local,
  unspecified, metadata, reserved/transition and documentation ranges. Private
  image servers supported by Rust are intentionally unavailable in this batch.
- Encoded response limit 8 MiB; decoded maximum 8 million pixels and 8192 per
  dimension, checked overflow-safely before decoding and checked again afterward.
  Header, connection and total request deadlines bound network work.
- MIME must match a recognized raster (or octet-stream with recognized signature).
  SVG is unsupported even when mislabeled; no SVG parser or active HTML execution.
  GIF decodes first frame only. Animated WebP is rejected, including animation
  markers after unknown RIFF chunks. This is not animation parity.
- Four workers, 64 cache entries including failures, 64 MiB conservative decoded
  accounting, 32 MiB current-owner queued/in-flight encoded-input accounting.
  Reset can leave at most four old-owner worker jobs holding their bounded raw
  input until cancellation/decode returns (each at most about 10.67 MiB); these
  are additional to the new owner budget, not a global 32 MiB hard ceiling.
  Fetched response bodies and decode scratch
  allocations are separately bounded by worker/pixel limits, not the cache budget.
- Runtime/session/path/workspace change cancels the prior owner, increments epoch,
  clears cache and queued jobs. Old completion cannot publish into a replacement
  owner; native element keys include owner epoch and URL hash to reject held presses.
  Close cancels pending work and releases retained cache/transport state.
- Completed entries retain URL hashes, not raw URLs/data/tokens. Static errors do
  not echo addresses. No production exported transport/dial injection API exists.

## Evidence

Red-before mounted data-image test observed the permanent alt placeholder instead
of a 160×80 image (`markdown-image-red.log`). Final mounted tests inspect real
native bounds **and red raster pixels**, not labels alone:

- data PNG rendered and naturally sized;
- standalone HTML image with ignored `onerror`, data preview click/Escape, SVG fallback;
- mixed local file and data image preserves both real rasters;
- held press across A→B→A before a frame cannot activate replacement owner;
- 1200×600 image fits a 400px content area without aspect distortion/cropping;
- existing cross-message Markdown/alert selection and session-reset selection tests.

Package race tests use only generated bytes, fake resolver/dial functions, and
controlled local httptest servers. They cover vetted-IP dialing, mixed DNS answer
rejection, all-hop redirect checks and header stripping, limits/MIME/SVG,
first GIF frame, animated WebP rejection, cancellation, bounded failures/cache,
worker/pending limits, stale-owner completion and failed partial bitmap rejection.
No live private/public image host, credentials, user data or user Mac was used.

Logs are in `/workspace/shared/orbit-toolchains-continued/`:
`markdown-loader-freeze-race.log`, `markdown-image-freeze-race.log`,
`markdown-image-vet.log`. Parent integration must rerun its aggregate gates on the
combined source. These are mounted software/native tests, **not hosted macOS
pixel recapture or proof of whole migration parity**.

## Independent review correction: real workspace service boundary

Read-only review found that `changeWorkspaceServices` writes `Model.Workspace`
before the next snapshot. Snapshot-only owner detection therefore misses service
A→B→A, or failed session transitions. The actual mounted controller/service test
was red: a held old-owner image opened after the roundtrip. All four snapshot
owner dimensions also retained the old preview reference. The follow-on correction
uses one owner-reset helper at snapshot changes **and before actual service path
changes**, canceling cache work and closing/clearing preview. A same-path service
refresh preserves normal held input. This does not reset unrelated navigation.
Evidence: `markdown-image-owner-red.log`, `markdown-image-owner-race.log`,
`markdown-image-owner-vet.log` in the same toolchain log directory.
