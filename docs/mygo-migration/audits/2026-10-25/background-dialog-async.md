# Background image native dialog: asynchronous owner dispatch

Source: Rust `crates/orbit-pi/src/app/settings.rs::background_choose` (around 6572) explicitly uses `rfd::AsyncFileDialog` and returns its result to the app owner. Pinned MyGo dialog methods permit calling from any goroutine; the existing Go `BrowseBackground` synchronously waited during its UI action.

The Go hook now uses the same off-main native wait / UI completion queue as workspace and attachment dialogs. The real native panel, title, image extensions, selection and processing pipeline are unchanged. A single pending native dialog prevents repeated clicks and stacking across picker kinds. The UI callback rejects replaced/destroyed/closed windows, closed background state and any newer background generation (including reset). Background preference is global, so ordinary page or task navigation does not discard the user's confirmed choice. No native/UI object is mutated by the waiting worker. Existing image processing remains the serialized background worker.

Focused race tests exercise action-return while a synthetic native wait remains blocked, production UI rendering during that wait, singleton protection, Unicode/space path loading through the real image pipeline, cancellation, error, later reset, window replacement and close. Native confirmation is not proven by these tests. Existing native AX confirmation remains blocked; no forced modal result or user-machine operation was attempted. This is a source-matched event-loop correction, not evidence that the user's observed hang is reproduced or resolved.
