## 明日建议按这 8 组正常流程验收

只用无敏感内容的临时项目、临时文件与会话。无需重置现有模型凭据，不用真实删除、提交、评论或 PR 合并来验证基础界面。

1. **启动与工作区（先过阻断项）**：启动 .4，确认已有 Pi 模型可见；打开临时目录，取消一次再确认一次，再切换到第二目录。若卡住，记下最后操作，先停止依赖该步骤的测试。
2. **输入和真实对话**：中文输入法、emoji、Shift+Enter、撤销；选模型做一次无副作用短请求。流式期间加 follow-up/steer、清空待发队列、停止、再发送，检查草稿与忙碌状态。
3. **附件与消息**：粘贴/拖入小图、移除、预览；在文本中间插入文件（.4 已知会追加到末尾）。检查代码复制、跨消息选择、查找、滚动离开后回到底部。
4. **文件与保存**：打开两份临时文本，多 tab 编辑，自动保存后关闭/重开；外部修改 clean 文件应刷新，dirty 文件应保留修改并提示冲突。测试中文/快捷键不应误发聊天。
5. **Git 与 Review**：同一临时文件制造 staged 与 unstaged 内容，切换 Changes/Review 来源、unified/split/wrap、长行和大 diff；取消 Discard 不应改文件。两轮文件修改后检查 Last Turn 与历史 turn 不被下一轮覆盖。
6. **终端与窗口恢复**：两个终端 tab、不同工作区 cwd、Ctrl+C/粘贴/中文；exit 后观察已知缺失的重启入口。关闭窗口但不 Quit，再从 Dock 打开，检查会话和后台任务仍在。
7. **设置、模型与 Usage**：搜索设置、换主题/语言/密度后重开；模型收藏/最近和思考强度；Usage 日期、过滤、排序、分页、列和取消导出，再导出到临时文件。看数据和边界，不只看面板出现。
8. **扩展与状态**：Skills/Plugins/MCP 先只读对照现有配置。若有安全的本地 fixture，再测问卷 Back/Submit、审批 Cancel、切会话及重开；不要为验收授予高风险工具。MCP 应用状态缺口仍须单独关注。

记录每项“通过 / 失败 / 未测”，失败记录版本、最后一步、预期与实际即可。不要把未触发的错误/取消/重开分支顺带标为通过。

## 日志与已知边界

.4 本地日志路径：`~/Library/Application Support/Orbit Go Test/Home/.orbit-pi/logs/app.log`。上一段为 `app.log.1`，各最多 1 MiB；仅记录固定阶段、结果和耗时，不记录对话、密钥、环境变量或工作区路径，不自动上传。

Pi 正常读取 `~/.pi/agent` 或指定的 `PI_CODING_AGENT_DIR`；原生 Pi 可能正常迁移配置或刷新登录信息，不能承诺完全不写原文件。原版自动更新功能也不能在本测试包中验收成功：尚无 Go 签名更新 feed/key，不能使用 Rust 的更新包代替。
