The initial file-only Controller stage below is historical. Final live-task routing is superseded by `palette-rename-unpersisted-contract.md`: Pi supports a named, not-yet-persisted task, so exact captured live targets use the existing command lease, while cold saved rows retain file metadata ownership. Do not integrate the original90ebb file-only stage alone.

The bounded correction owns a Rename intent with displayed name, path, session ID, runtime ID and workspace. Owner changes revoke it at snapshot/service boundaries; a newer Prompt or dismissal revokes it; submit consumes it once before dispatch and sends the captured path explicitly. Rename alone gets an intent-specific native modal key, preventing a held Save from activating a replacement Rename. Other Prompt keys, the frozen Delete implementation and backend command/metadata leases remain unchanged. The Controller must also route explicit saved paths through existing RenameSavedSession file ownership/metadata leases, never compare against a possibly stale UI snapshot and fall back to the manager’s current task. Pathless requests are rejected instead of inferring a new current target. Both existing Rename producers (palette and sidebar row) provide the saved path. A title-only model update does not change the originally displayed task identity.

This is target-safety correction, not complete Rust details-popover/rename UX parity or OS accessibility validation. Backend ownership/lease validation remains authoritative; no backend fallback or concurrency policy is weakened.
